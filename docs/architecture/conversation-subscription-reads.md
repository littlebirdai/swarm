# Conversation reads in subscriptions

A subscription that reads a conversation can run again when transcript ingest updates the conversation, even if its answer only uses a title or an access flag. This inventory follows query references in the web and mobile clients, the web sync registry, and CLI and daemon WebSocket subscriptions to their server handlers and shared read helpers. It includes conditional reads such as access checks and rollout fallbacks. One-shot fetches and mutations are outside this inventory.

## Narrow reads already in use

`pendingMessages.getPendingMessagesForDaemon` reads the delivery projection in `session_starts`. It falls back to a conversation when the projection is absent. `pendingMessages.getMessageStatus` and `collab.collabRequests` use the projected runner for their corresponding access checks. `notifications.list`, `sessionDecisions.listForUser`, and `sessionDecisions.listOpenForLines` use the session card for display fields, with a fallback for older rows.

The first remaining daemon path to move is `executionBindings.listExecutionWork`. It fans out over fenced heads and needs only the safety verdict. The rollout flag is `EXECUTION_WORK_SESSION_CARD`. With it enabled, a projected verdict supplies the safety check. A row without the verdict still uses the conversation until the session-start projection is refreshed. Transcript viewers and views that display changing activity still need access to those changes.
