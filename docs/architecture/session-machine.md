`packages/sessions/src/agentStatus.ts` defines the accepted agent status vocabulary. `packages/sessions/src/pendingStatus.ts` defines the legacy message vocabulary. `liveness`, `workState`, and `threadState` in the same package supply projections and display vocabulary. They do not persist status.

## Differences from the target

- Heartbeats and status posts accept status values. They can overwrite agent status independently. A heartbeat timeout also removes a registry row without positive process-exit evidence. The reducer uses facts and keeps runtime disposition separate from contact.
- A daemon status change or a timestamp can imply that a turn ended. Today the managed row lacks a durable turn ID. The reducer requires a named provider turn. It never infers an end from a change in activity.
- Legacy healers can retry a stale `pending` row or an unverified `injected` row based on time and readiness. A busy agent or an aged control message can imply delivery. These signals do not prove whether the effect occurred under the current attempt. The reducer requires a receipt, correlated evidence, or proof of no effect. Time alone cannot retry or acknowledge input.
- The fenced writer maintains three state copies across the queue row, attempt, and execution head. The reducer uses one delivery record per ID and derives the active head from order. It retains recent attempt IDs and an attempt number to reject replays.
- The live successor path can stage a second binding and requires old deliveries to drain or be cancelled before activation. The Delivery model can reopen after proof of exit and reconcile outstanding input. The reducer applies the model to the current epoch. It returns unstarted permits, preserves uncertainty after a start, and accepts proof under the new fence.
- The live startup retry reuses an operation ID. The edge fence uses an opaque token. The reducer accepts a retry under a fresh token so a late result from the previous attempt cannot settle the retry.
- The conversation can reactivate on enqueue or on a direct status mutation today. The reducer requires a successor epoch to reopen a completed session. A new turn in the current epoch can advance the turn slot but cannot reopen the old turn ID.
- The current edge package has session, run, turn, prompt, delivery, attempt, and run fence identities. Its permit request has no expected turn. The pure contract takes that expectation separately. The claim row owns the baton holder, the pending takeover, and the acknowledgement that permits the new holder. The adapter supplies the numbered `takeover.fence` fact when the claim fence changes. A raised fence blocks `delivery.start`. The machine checks the fence again before the effect. The terminal typing claim stays outside this reducer.

## Visible state

| Current visible state              | Reducer source                                                                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Provider error or API-error park   | The provider error fact stores its class, message, and retryability. A new turn clears the report. Current API-error and safety incidents also supply `pendingApiError`. |
| Hibernated or intentionally parked | `parked` distinguishes a deliberate release from process loss. The pin determines the rest verdict. Parking alone supplies no dormancy verdict.                          |
| Hosted queued or stopped           | `hostedQueued` signals hosted work the engine can start. `hostedStopped` signals a stop with no live turn.                                                               |
| Killed or completed                | `killed` records retirement and always projects idle. Completion remains a lifecycle state. A completed run with unfinished work can still need input.                   |
| Compacting                         | `compacting` projects working during live execution without an unresolved error or ambiguous delivery.                                                                   |

The projection uses the inbox vocabulary, including `needs_input`. The parity tests compare corresponding inputs to the current classifier. A running turn projects working only while execution is live. A started delivery projects working only while the run accepts input. Lease expiry needs input when a turn or pending work exists. A held row supplies no pending work. The live classifier also accepts user rest and snooze overrides through its existing placement inputs.

## Contract boundary

`@codecast/session-contract` exports `sessionMachine.initial`, `sessionMachine.apply`, and `sessionMachine.whoActsNext`. Its separate package keeps the runtime entry point free of dependencies and lets the existing sessions package retain its display functions. The reducer uses type-only imports from the existing edge contract. One copy of the table serves all four runtimes.

The caller parses edge input, validates process evidence and actor rights, and supplies local facts with the current scope. The caller supplies provider events in increasing canonical sequence across epochs. It buffers gaps before reduction if events arrive out of order. The reducer accepts only safe integer sequences above its accepted watermark. A receipt identifies the delivery even after a later turn starts. A local adapter must also check the start permit against the turn and baton before it accepts that fact. A successor accepts only the exact next epoch and requires proof that the predecessor stopped or entered quarantine. The successor retains the takeover fence and its revision until the claim owner clears it.

The caller must commit the result before it dispatches an effect. Before the hand-over, the machine must check the epoch, attempt, turn, and applicable claim again. A duplicate start returns no new delivery effect. The machine must recover a committed attempt before it considers an external retry.

A claimed, started, or ambiguous delivery occupies the single in-flight slot. With the slot empty, the first pending row is eligible. During a running turn, the first pending steer is eligible. Held rows do not occupy the slot. A steer carries the sender’s expected turn through both permit and start. A waiting queue entry can become eligible when its turn ends. A started row without proof stays unresolved. A successor can reconcile it by receipt or by evidence of no effect. An explicit resend retires the old delivery and assigns a distinct ID and a new sequence.

The reducer retains up to 32 terminal deliveries and another 32 pruned delivery IDs, plus the 32 most recent turn IDs, run tokens, and attempts per delivery. It keeps all open deliveries. The inbox watermark survives pruning and epoch changes. Claim and permit adapters assign increasing numbers per epoch and delivery, respectively, and preserve them on retransmission. The numbers fence older facts after their opaque IDs leave the recent history. A missing or disallowed transition returns the same state and an empty effect list. The caller can use that result to return a protocol refusal where necessary.
