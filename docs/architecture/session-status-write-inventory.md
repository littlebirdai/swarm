# Convex session status writers

The `managed_sessions` table stores `agent_status`, two status timestamps, a boundary flag, `turn_completed_at`, and `hibernated_at`. It has no separate `status` field. The `conversations` table stores `status`, the hosted stop, the thread pin, and the agent status probe. The probe holds evidence for a later status change. The inbox queries join managed status and turn stamps at read time. The hosted engine stores its turn status in `assistant_turns.status`.

The table gives the closest `@codecast/session-contract` fact for each writer. A gap means that the current writer needs evidence, a projection input, or an operation that the contract does not supply. File paths start at `apps/server/convex`.

The guard names each legacy write site. Dispatch can also send the thread pin through `favoriteViewWrites.ts` and `patchConversationThroughFavoriteView`. The guard checks both dispatch paths against the fields that dispatch can edit.

The file-level source guard checks literal keys and direct assignments for distinctive fields and can miss indirect or computed writes.

The heartbeat handlers use `lib/sessionStatusWriter.ts` for the registry patch and side-row writes. Authorization, registry lookups, and scheduled checks remain in `managedSessions.ts`.

## Heartbeat replay gaps

The replay compares the legacy agent status with the contract's turn state. It supplies each provider event only when the fixture observes it.

| Missing event   | Legacy agent status  | Contract turn state | Reason                                             |
| --------------- | -------------------- | ------------------- | -------------------------------------------------- |
| `turn.started`  | `working`            | No turn             | A heartbeat has no turn ID or start event.         |
| `prompt.opened` | `permission_blocked` | Running             | A heartbeat has no prompt ID or open event.        |
| `turn.ended`    | `idle`               | Blocked             | A heartbeat gives no evidence that the turn ended. |

A later matching provider event closes each gap in the fixture. A stale heartbeat cannot change the stored agent status after the turn ends.

## Pending-message healers

These paths also change delivery state. Their delivery fields are outside the status guard.

| File                 | Writer                                                                                                    | Field                         | Trigger and caller                                                                        | Contract fact or gap                                                                                                                               |
| -------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pendingMessages.ts` | `healStuckCandidates` via `rependPendingMessage`                                                          | Message status to `pending`   | The stuck-message job retries eligible input, including input for a dead session.         | `delivery.returned` for an unstarted permit or `delivery.settle` with proof of no effect. Gap for retries based only on elapsed time or readiness. |
| `pendingMessages.ts` | `healStuckCandidates` via `failUnconfirmed`                                                               | Message status to `failed`    | The stuck-message job finds a verified paste with no echo.                                | `delivery.settle` with `in_doubt`. The reducer retains ambiguity.                                                                                  |
| `pendingMessages.ts` | `healStuckCandidates` via `markPendingDelivered`                                                          | Message status to `delivered` | The stuck-message job clears a legacy control row.                                        | Gap when there is no receipt or correlated effect.                                                                                                 |
| `pendingMessages.ts` | `healStuckCandidates`, `notifyStuckSend`                                                                  | Message status to `cancelled` | The stuck-message job finds expired input or a gone recipient.                            | `inbox.cancelled` for unstarted input. | `pendingMessages.ts` | `cancelOldPendingMessages`                                                                                | Message status to `cancelled` | A person invokes the internal mutation to cancel old legacy rows.                         | `inbox.cancelled` for unstarted input. | `pendingMessages.ts` | `ackInjectedForDaemon`                                                                                    | Message status to `delivered` | The daemon reports transcript evidence.                                                   | `delivery.reconciled` or a correlated provider receipt.                                                                                            |

Registry deletion also removes any stored status. Registration replaces obsolete rows, conversation linkage removes duplicates, unregister removes a daemon row, and the stale-session job reaps expired rows. These are registry operations. None alone establishes runtime exit.

The run lease and fenced delivery writers remain in their existing modules. See [the session contract inventory](session-machine.md) for their transitions.
