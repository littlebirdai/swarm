# Convex session status writers

The `managed_sessions` table stores `agent_status`, two status timestamps, a boundary flag, `turn_completed_at`, and `hibernated_at`. It has no separate `status` field. The `conversations` table stores `status`, the hosted stop, the thread pin, and the agent status probe. The probe holds evidence for a later status change. The inbox queries join managed status and turn stamps at read time. The hosted engine stores its turn status in `assistant_turns.status`.

The table gives the closest `@codecast/session-contract` fact for each writer. A gap means that the current writer needs evidence, a projection input, or an operation that the contract does not supply. File paths start at `apps/server/convex`.

Dispatch can also send the thread pin through `favoriteViewWrites.ts` and `patchConversationThroughFavoriteView`.

The guard is file level. It finds literal keys and direct assignments of the distinctive fields only, and not `conversations.status` or the thread state. It can miss an indirect or computed write. It also matches a type or a read projection that has one of the field names. Put such a file in the list, with the reason.

The heartbeat handlers use `lib/sessionStatusWriter.ts` for the registry patch and side-row writes. The same module writes daemon and hosted status and creates the hosted registry row. Authorization, the daemon lookup, and reactions to status changes remain in `managedSessions.ts`.

## Heartbeat replay gaps

The replay compares the legacy agent status with the contract's turn state. It supplies each provider event only when the fixture observes it.

| Missing event   | Legacy agent status  | Contract turn state | Reason                                             |
| --------------- | -------------------- | ------------------- | -------------------------------------------------- |
| `turn.started`  | `working`            | No turn             | A heartbeat has no turn ID or start event.         |
| `prompt.opened` | `permission_blocked` | Running             | A heartbeat has no prompt ID or open event.        |
| `turn.ended`    | `idle`               | Blocked             | A heartbeat gives no evidence that the turn ended. |

A later matching provider event closes each gap in the fixture. A stale heartbeat cannot change the stored agent status after the turn ends.

## Managed status write rules

Each report replaces the boundary flag. A report without a boundary clears that flag. The writer keeps the last turn completion time until a report supplies a new one. A resume can clear the park time with `hibernated_at: null`.

The writer changes `agent_status_updated_at` only when the status changes. Idle detection uses that time. A fresh report of open tasks refreshes their timestamp even when the list is the same. An active status refreshes the heartbeat so a stale heartbeat does not override the report.

The hosted row has no daemon process. Its heartbeat shows that a hosted turn is active. Daemon liveness and stale-row cleanup skip this row. The writer refuses to mark a local session as hosted so that cleanup can still find it.

## Managed status replay gaps

The replay sends status reports through `updateAgentStatus`. It supplies the reducer with the provider events that the fixture observes.

| Report                        | Legacy registry | Contract turn | Reason                                                                                      |
| ----------------------------- | --------------- | ------------- | ------------------------------------------------------------------------------------------- |
| Presumed work                 | Working         | No turn       | The report can paint the session as working before the provider starts a turn.              |
| Session boundary              | Idle            | Running       | A boundary report can reset the visible status without a turn end event.                    |
| Uncorrelated completion stamp | Idle            | Running       | The legacy path can release turn work on a timestamp that identifies no provider turn.      |
| Hibernate                     | Parked          | Ended         | The registry stores a park timestamp. The reducer accepts park state as a projection input. |

## Hosted turn and thread pin rules

The stop marker lets the inbox show the reason without a transcript read. A new turn clears the stop after it reserves wallet funds. A pin write replaces the previous result and its timestamp so it cannot carry a report from an earlier station.

The hosted start calls the shared writer for its managed-session row. The common conversation initializer also serves daemon starts and still sets `conversations.status`.

## Hosted turn and thread pin replay gaps

| Event                              | Legacy write                                              | Reducer result                                                                                    |
| ---------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| All hosted slots are full          | The engine creates a queued turn.                         | The turn state stays empty before a provider start. Queue capacity is an input to the projection. |
| Wallet limit stops a turn          | The engine marks the turn done and records a budget stop. | The turn stays running without a turn end fact. The stop marker is an input to the projection.    |

## Conversation lifecycle writes

The shared writer stores the status and inbox fields for starts, forks, daemon reports, device moves, and restarts. It also stores the kill, close, and stash changes from `killConversation`, `applyHideTransition`, and `hideNestedChildren`. CLI visibility and retirement use it for their first inbox patch. A blocked pin uses it to clear the stash and dismissal.

`dispatch.applyPatches` clears the kill stamp on restore through the shared writer. Its generic patch still accepts editable fields, including close and stash fields. Keep this patch together because one request can update several fields in one write. The favorite view path forwards the same patch and also updates the favorite view. `sessionGoals.takeDownGoalPin` only clears the thread pin.

`createConversation` still creates the active row from transcript ingest and can complete the parent on plan handoff. The trace harness rejects the existing `users.first_session_synced_at` write during this path because the schema has no such field.

These paths still write inbox stamps directly.

- `inboxFilters.ts` uses `restoreToInbox` to clear stash and dismissal on a hidden session with no kill stamp.
- `sessionOwnership.ts` uses `unhide` to clear dismissal, stash, and the stash-hidden flag when a session gains an owner.
- `agentTasks.ts` uses `settleRunConversation` and `linkRunConversation` to stash settled or superseded task runs. `lib/agentTaskRows.ts` uses `stampRunConversation` to stash eligible recurring runs.
- `daemonCommandUtils.ts` uses `resumeConversationSession` to clear dismissal when a person resumes a closed session.
- In `conversations.ts`, `createConversation` can stash an ingested fork through `daemonForkFields` and dismiss a plan-handoff parent. `dismissFromInbox` dismisses a row on request. `drainStaleDismiss` and `healHistoricalUpdatedAt` dismiss old rows. `linkSessions` and `adminLinkChildrenBySessionId` dismiss linked children. `adminUnlinkSession` clears that dismissal.
- `lib/orgSessionFiling.ts` uses `applyFileSession` to dismiss a session filed as done.
- `migrations.ts` uses `clearCopiedChildStashStamps` and `clearCopiedStashPage` to clear legacy stash stamps and flags copied to children. `debugTmp.ts` uses `unnestSelfParented` to clear dismissal on self-linked rows.
- Delivery paths in `pendingMessages.ts`, `pendingMessageWrites.ts`, and `executionBindings.ts` clear inbox stamps when they reopen a session.

## Conversation replay gaps

The replay sends a provider end event when the fixture has one. For each reopen case, the previous run has ended and the fixture has no proof to authorize a successor.

| Legacy action                                               | Stored status | Contract status | Reason                                                                                    |
| ----------------------------------------------------------- | ------------- | --------------- | ----------------------------------------------------------------------------------------- |
| Kill, hide with kill, or retire                             | Completed     | Active          | The request can set completion before the provider ends the session or the runtime exits. |
| Activate, restart a row, recover a twin, or replace a ghost | Active        | Completed       | The write can reopen the row before the contract authorizes a successor.                  |
| Move, reassign, or reparent                                 | Active        | Completed       | The move can reopen the row before the contract authorizes a successor.                   |
| Copy a shared transcript                                    | Completed     | Active          | A transcript copy starts completed even though it has no execution end event.             |

Close, stash, restore, and a blocked pin can change inbox placement while status stays the same. The trace checks the stored placement. The reducer accepts placement as a projection input.

## Workflow log replay gaps

The replay covers workflow starts from the web and CLI, progress reports, and the stash backfill. The workflow run keeps its own status on `workflow_runs`.

| Event                                                          | Legacy conversation write                                                                                | Contract result                                                                          |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| A task run starts or the stash backfill finds an old task log  | The log has a stash timestamp and a stash-hidden flag.                                                   | The session stays active. Workflow ownership and the stash fields are projection inputs. |
| A completed or failed report includes a progress message       | The log or the existing host session becomes completed in the same patch that updates its message count. | The session stays active without a provider end event or verified runtime exit.          |
| A completed report names the start node or omits node progress | The workflow run completes without a conversation patch.                                                 | The session stays active. Workflow completion alone supplies no session end fact.        |

## Pending-message replay gaps

| Event                                                                          | Legacy result                                                                                                            | Contract result                                                                               |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Elapsed time or readiness allows a retry, including after a process disappears | The same row goes back to `pending`. Dead-session recovery also records one revival.                                     | Elapsed time, readiness, and offline state do not prove that a started attempt had no effect. |
| A daemon holds, retries, or resets a row, or a session resumes                 | The same row goes back to `pending` and clears the paste stamp. The hold can keep the retry count and record its screen. | Holds and screens are projection data. A started attempt needs proof of no effect.            |
| A person retries an unconfirmed send                                           | The same row goes back to `pending` and can carry a force flag.                                                          | After explicit abandonment, a resend uses a new delivery ID and sequence.                     |
| A verified paste receives no echo                                              | The row becomes `failed` with a reason and can notify its sender.                                                        | An in-doubt settlement preserves ambiguity and keeps the delivery slot occupied.              |
| A control row ages, or an old daemon acknowledges every injected row           | The selected rows become `delivered` without a per-message transcript receipt.                                           | A started delivery needs evidence of an applied effect or a correlated receipt.               |
| An unconfirmed row expires                                                     | The healer cancels the row and clears its reason.                                                                        | Elapsed time cannot abandon an ambiguous attempt.                                             |
| The recipient disappears                                                       | The healer cancels the row after it handles the sender receipt.                                                          | It can cancel an unstarted row. Recipient loss alone cannot settle a started attempt.         |
| A person cancels old rows in bulk                                              | The mutation cancels selected rows, including submitted rows, and keeps any unconfirmed reason.                          | Started ambiguous input requires explicit abandonment.                                        |
| A pane refuses input before submission                                         | The old row becomes `cancelled`. Recovery can start a new pane and enqueue a new row.                                    | Proof of no effect settles the old attempt. Restart and enqueue remain separate facts.        |

A daemon with a correlated transcript acknowledgment records the transcript link before it marks the pending row delivered. This path has per-message evidence. The healer skips fenced rows.

Other direct queue writes remain. `enqueuePendingMessage` releases deferred input, `mergeQueuedForUser` cancels the absorbed row, and `cancelPendingMessageForUser` cancels an unstarted fenced row. In `pendingMessageWrites.ts`, `insertEnqueuedPendingMessage` sets the initial status and `releaseQueuedRows` publishes held rows. `orgRoles.performRetireRole` releases or cancels held rows.

Registry deletion also removes any stored status. Registration replaces obsolete rows, conversation linkage removes duplicates, unregister removes a daemon row, and the stale-session job reaps expired rows. These are registry operations. None alone establishes runtime exit.

The run lease and fenced delivery writers remain in their existing modules. `lib/edge/runEvents.ts` writes status and turn state to `run_turn_projections`. See [the session contract inventory](session-machine.md) for run and delivery transitions.
